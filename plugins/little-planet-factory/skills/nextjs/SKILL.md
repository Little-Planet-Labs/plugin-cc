# Next.js

This skill covers Next.js itself, on any host. Generic React discipline, stack detection, and the no-dev-server rule live in `react-apps`. What a page needs for SEO, icons, titles, and social cards lives in `web-design`. This skill covers how to implement those in Next. When the project deploys to Vercel, load `vercel` as well.

Version-specific rules name the version they were verified on. Check the project's installed `next` version before applying one, and follow what that version does.

## Firm defaults

Apply these unless the user asks otherwise.

- **Dynamic Open Graph image.** Every site gets an OG image generated by the `opengraph-image` file convention with `ImageResponse` from `next/og`. Not a static PNG in `public/`, and not a hand-rolled route handler under `app/api/`. See the Open Graph images section.
- **`next/image`, never a plain `<img>`.** The one structural exception is JSX inside `ImageResponse`. Satori calls function components as plain functions without React's renderer, so hooks throw, and `next/image` inside `ImageResponse` fails the prerender. Use a plain `<img>` there, with a data URI or an absolute URL. Don't disable `@next/next/no-img-element`. When an image genuinely can't be optimized, use the rule's documented escape hatches: `unoptimized`, a `<picture>` element, or a custom loader.
- **Vercel Web Analytics and Speed Insights.** On Vercel, apply the `vercel` skill's Analytics and Speed Insights rule. If the host isn't known yet, ask the user whether it deploys to Vercel.

## Metadata API

- **Set `metadataBase` explicitly in the root layout.**
  - A relative URL in a URL-based field without it is a build error.
  - For file-convention OG and Twitter images, Next falls back to `https://${VERCEL_BRANCH_URL || VERCEL_URL}` on Vercel previews, overriding even an explicit `metadataBase` there. Everywhere else it falls back to `metadataBase || VERCEL_PROJECT_PRODUCTION_URL || http://localhost:3000`.
  - So a self-hosted build without it ships `localhost` OG URLs.
- **Tab titles** come from `metadata.title`, with a `template` in the root layout: `{ template: '%s - Site', default: 'Site' }`.
  - The default separator is a spaced hyphen; Google allows a hyphen, colon, or pipe. Follow `web-design`'s title rules: never an em-dash.
  - `title.default` is required with a template.
  - `title.template` applies only to child segments, not the segment that defines it, so `app/page.tsx`'s own title isn't templated.
- **Dynamic routes use `generateMetadata`.** Its `params` is a Promise in Next 16; await it.
- **Crawlability** through `app/sitemap.ts` and `app/robots.ts`, implementing `web-design`'s robots and sitemap rules.

## Icons

- **Pick one mechanism**: the App Router file conventions (`icon.*`, `apple-icon.*`, `manifest.*`), or `public/` plus `metadata.icons`/`metadata.manifest`. When `metadata.icons` is set, Next silently drops the `app/icon.*` and `app/apple-icon.*` conventions. `app/favicon.ico` is always emitted, so also declaring `/favicon.ico` in `icons` duplicates it. `app/manifest.*` overrides `metadata.manifest`. (Verified in the Next 16.3.0 source, `lib/metadata/resolve-metadata.js`, and a build.)
- Which icons a site needs is `web-design`'s call.

## Open Graph images

- **The file.** `app/opengraph-image.tsx` for the site, and `app/<route>/opengraph-image.tsx` for a route that needs its own card. The default export is `async function Image({ params }: { params: Promise<{ slug: string }> })`; `params` has been a Promise since 16.0.0. Optional exports: `alt`, `size` (`{ width, height }`), and `contentType`. It must return a `Response`, which `ImageResponse` satisfies. `twitter-image` is the parallel convention, and `generateImageMetadata` produces several images for one route.
- **It's a special Route Handler.** It's statically optimized (built at build time and cached) unless it uses request-time APIs or uncached data, and it accepts route segment config.
- **Request-time APIs make it dynamic.** `cookies()` or `headers()` in an `opengraph-image` turn the route dynamic (ƒ), so it loses build-time caching. Keep it a pure function of the URL.
- **Node runtime.** The Edge runtime is deprecated in Next 16 and Node is the default. Don't set `runtime = 'edge'` on OG routes or any new route.
- **Fonts** are read with `readFile` from `node:fs/promises` and `join(process.cwd(), 'assets/…')`, once at module scope, not fetched through `import.meta.url` (which fails on Node). `ImageResponse` accepts ttf, otf, and woff only. Not `.woff2` (`Unsupported OpenType signature wOF2`), and not variable fonts: a font with an `fvar` table makes the satori bundled with Next 16.3 throw `TypeError … at parseFvarAxis` at render time, while typecheck and build pass. Keep a static `.ttf` of the site font for OG use.
- **The `ImageResponse` bundle is capped at 500KB**, including JSX, CSS, fonts, and images. Local raster assets are read with `readFile` into a base64 data URI or an `ArrayBuffer`.
- **Layout is flexbox and a CSS subset.** Satori's `display` accepts `flex`, `block`, `contents`, or `none`; grid throws. Every `<div>` with more than one child needs an explicit `display: flex`, `contents`, or `none`.
- **Render every new or changed card once locally**, through a build or by calling `ImageResponse` directly. Font and layout failures appear only at render time.

## next/image

- **`src` and `alt` are required.** Set `width` and `height` unless the image is statically imported or uses `fill`.
- **`fill`** needs a positioned parent. `sizes` is required with `fill` or with responsive CSS sizing; without it the browser assumes `100vw`.
- **`priority` is deprecated as of 16.0.0** in favor of `preload`. For most above-the-fold images the docs recommend `loading="eager"` or `fetchPriority="high"` instead.
- **Remote images** go through `images.remotePatterns` (URL objects or the object form). `images.domains` is deprecated.
- **SVGs aren't optimized.** Prefer `unoptimized`, which is automatic when `src` ends in `.svg`. `dangerouslyAllowSVG` also needs a `contentSecurityPolicy`.
- **`images.qualities` defaults to `[75]` in Next 16** and acts as an allowlist; a `quality` prop outside it is coerced to the nearest allowed value.
- **Local images with query strings** need a matching `images.localPatterns[].search` in Next 16.

## Dynamic params

Page and layout params arrive percent-encoded in every environment (Next runs `encodeURIComponent` on them in `get-dynamic-param.js`). Decode with `try { decodeURIComponent(v) } catch { v }`. Route Handler params arrive decoded; don't decode them twice. (Verified at runtime on 16.3.6.)

## Proxy and middleware

- **Next 16 renamed `middleware.ts` to `proxy.ts`.** A proxy file exports `proxy` (or a default export) plus `config`. (Verified on 16.3.0.)
  - A wrong function name fails the build ("Proxy is missing expected function export name"). A non-literal matcher also fails the build.
  - A misnamed config export (for example `proxyConfig`) builds fine and silently compiles to `/:path*`, gating every route. Check `.next/server/functions-config-manifest.json`.
  - The `runtime` option isn't allowed in proxy files, which run on Node.
  - `middleware.ts` still works but is deprecated, and it runs on Edge (its matcher lands in `middleware-manifest.json`).

## Hydration safety

- **No `Date.now()` in render.** `react-hooks/purity` is an error in eslint-config-next 16 (eslint-plugin-react-hooks 7.1.1). It flags `Date.now()` in any component render, server or client. Compute time-derived values in the data layer and pass them down.
- **Locale-formatted dates differ between server and client.** The server formats in its own time zone (UTC on most hosts), the client in the local one, so hydration mismatches. Fixes: `useMounted` for primary timestamps (costs a flash), `suppressHydrationWarning` for secondary ones, or `useSyncExternalStore` with a UTC server snapshot and a local client snapshot (the lint-clean option, since `react-hooks/set-state-in-effect` is an error in eslint-config-next 16).

## Caching (Next 16)

- **`cacheComponents` and `useSearchParams()`.** A client component calling `useSearchParams()` must sit inside `<Suspense>`, or `next build` fails (CLIENT_HOOK_DYNAMIC). On a static route that subtree renders only in the browser, so the prerendered HTML holds the fallback. `usePathname()` and `useParams()` render into the static HTML, except in fallback shells. (Verified on 16.3.6.)
- **Which GET Route Handlers run at build.**
  - Without `cacheComponents`, `next build` runs a GET handler only if it opts into static generation: `dynamic = 'force-static'` or `'error'`, `revalidate` > 0 or `false` (not `0`), or `generateStaticParams`. A no-config GET is dynamic.
  - With `cacheComponents`, every GET runs at build, and route segment config (`dynamic`, `revalidate`, `runtime`, …) is a build error.
  - Put `await connection()`, or a read of the request, before any DB work to keep a handler out of the build.
- **`revalidateTag(tag, 'max')` only marks the entry stale**, so the next request still gets old data. For webhook- or cron-driven invalidation use `revalidateTag(tag, { expire: 0 })`. The single-argument `revalidateTag(tag)` is deprecated (a type error, plus a runtime warning).
- **`updateTag` is immediate but works only in Server Actions.** It throws in Route Handlers.
- **Cache scope.** `use cache` defaults to an in-memory LRU per instance and doesn't survive a new deploy; `use cache: remote` uses the configured `cacheHandlers`. `unstable_cache` is soft-deprecated in favor of `use cache`.

## Server Actions and RSC boundaries

- **A `"use server"` file may export only async functions at the value level.** A stray exported const fails `next build` while `tsc` and ESLint pass. (Verified on 16.2.11 and 16.3.0.)
- **Props from Server to Client Components must be serializable.** Plain functions (icon components, formatters) aren't, unless they're Server Functions or exports of a `'use client'` module. Build such configs in a `'use client'` wrapper, or pass rendered JSX (`icon: <Icon />`).

## CSS and bundle size

- **App Router links every stylesheet reachable from the route's server-rendered module graph**, whether or not it renders. That includes CSS behind `await import()` in Server Components and behind SSR'd `next/dynamic`. To keep CSS off a route, load the module only on the client: `next/dynamic(…, { ssr: false })` from a `'use client'` component, or `import()` inside a client event handler or effect. One dead import in a shared module can put a library's stylesheet on every page that uses it. (Verified on 16.3.0 and 16.3.6, Turbopack and webpack.)

## Toolchain pins (as of Sep 2026)

- **Pin `typescript@^6` and `eslint@^9`.** eslint-config-next 16.3.x doesn't support TypeScript 7 (typescript-eslint 8.x supports `<6.1.0`) or ESLint 10 (eslint-plugin-react 7.37.5 calls `context.getFilename()`, which ESLint 10 removed).
- **No `next lint`.** It was removed in 16, and `next build` no longer lints. Run `eslint .` with a flat config.

## Splitting Next.js work across agents

These files each have a single owner, per the `react-apps` rule for shared files:

- `next.config.*`.
- The root `layout.tsx`, which holds the metadata (`metadataBase`, the title template, icons), `<Analytics />`, and `<SpeedInsights />`.
- `proxy.ts` or `middleware.ts`, and its matcher.
- `app/opengraph-image.tsx`, `app/sitemap.ts`, and `app/robots.ts`.

A route-level `opengraph-image` goes with its route's unit, along with that route's `generateMetadata`. Units that need a new remote image pattern, matcher entry, or root metadata field report the exact addition to the owner.

## Review focus

Inspecting Next.js changes, weight these: a plain `<img>` outside `ImageResponse`, or a disabled `no-img-element` rule; a missing, static, or route-handler OG image; a missing `metadataBase`; missing `<Analytics />` or `<SpeedInsights />` on a Vercel project; `priority` on `next/image` in 16+; `fill` without `sizes`; `cookies()` or `headers()` in OG routes; woff2 or variable fonts passed to `ImageResponse`; `Date.now()` in render; `useSearchParams()` without a Suspense boundary under `cacheComponents`; `revalidateTag(tag, 'max')` used for webhook or cron invalidation; GET handlers doing DB work at build under `cacheComponents`; stylesheets reachable through dead server imports; page params not decoded, or Route Handler params decoded twice; `"use server"` files exporting non-functions; a misnamed proxy `config` export; `metadata.icons` alongside `app/icon.*` conventions; an em-dash in a title template; and `runtime = 'edge'` on new routes.
